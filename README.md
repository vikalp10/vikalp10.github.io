# VKLP — a trading terminal that trades me

[vikalp10.github.io](https://vikalp10.github.io)

A portfolio site built as a Bloomberg-style trading terminal, where the security being
quoted is me. The repository is a **real Spring Boot application**; GitHub Pages can't run a
JVM, so the app renders *itself* to static HTML and JSON at build time and Pages serves that.

```
mvn spring-boot:run                              # live preview → http://localhost:8080
mvn -q -DskipTests package                       # build the jar
java -jar target/vklp-portfolio.jar --export     # render docs/ for GitHub Pages
```

## How it works

Data lives in Java, not in markup. `PortfolioData` is a `@Component` holding the whole site
as records — `Profile`, `Execution`, `Skill`, `Holding`, `NewsItem`, `Quote`, `Stat` — and it
is the only place any of it is written down. Two things read that bean:

| Mode | Entry point | What happens |
| --- | --- | --- |
| **Preview** | `mvn spring-boot:run` | `PageController` renders `templates/index.html`; `ApiController` serves `/api/*`; `DataController` serves `/data/*.json` |
| **Export** | `--export` | Web server off. `StaticSiteExporter` runs Thymeleaf's `TemplateEngine` over the same template into `docs/index.html`, Jackson writes `docs/data/*.json`, assets are copied across |

Because both paths render the same template from the same bean, the exported
`docs/index.html` is byte-identical to what the local server returns.

The browser only ever fetches relative `./data/*.json`, which exists in both modes — so the
same JavaScript runs locally and on Pages with no branching. There is no server on Pages, so
the ticking VKLP price is a seeded client-side random walk (`quote.json` supplies the seed,
drift and volatility). If the fetch fails entirely — opening `docs/index.html` straight off
the disk, where `file://` blocks it — the page falls back to the quote already rendered into
the markup and still works.

```
src/main/java/com/vikalp/portfolio/
  PortfolioApplication.java    two run modes, one jar
  data/PortfolioData.java      ← every fact on the site lives here
  model/                       Profile · Execution · Skill · Holding · NewsItem · Quote · Stat
  web/                         PageController · ApiController · DataController
  export/StaticSiteExporter.java   the "render myself to disk" bit
src/main/resources/
  templates/index.html         the terminal, panels [0]–[6]
  static/css/terminal.css      phosphor-green CRT theme
  static/js/terminal.js        boot sequence, random walk, canvas chart, command palette
docs/                          generated — this is what Pages serves
```

## Panels

`[0]` Security Profile · `[1]` Career Index · `[2]` Trade Blotter · `[3]` Order Book ·
`[4]` Portfolio Holdings · `[5]` News Wire · `[6]` Execute Order

Press <kbd>0</kbd>–<kbd>6</kbd> to jump between them, or <kbd>/</kbd> for the command palette.

## A note on the numbers

Everything in the blotter, order book, holdings and news wire is real. The *quote* is the
conceit — but each level is anchored to a real figure rather than invented, and the page says
so under the chart:

| Quote field | Anchored to |
| --- | --- |
| last / all-time high `120.00` | $120K annual savings |
| change `+8.30` | CGPA 8.3 / 10 |
| volume `500,000` | 500K+ records processed per day |
| 52-week low `40.00` | 40% faster queries post-migration |

Order-book depth bars represent an item's level in the book, not proficiency — the panel
header says that too.

## Deployment

GitHub Pages, `main` branch, `/docs` folder. `.github/workflows/pages.yml` rebuilds and
recommits `docs/` on every push to `main`, so the site never has to be regenerated by hand.
